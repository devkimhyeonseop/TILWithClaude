# 2026-11-25 주간 2일차: CCNA 개념(트렁킹), CCNA 덤프 10문제(9개 오답), 복습 5문제(2개 오답)

## 배운 것
- 오픽 데일리 3문제 완료
- **CCNA 개념 커리큘럼 Day 2: 트렁킹** — 802.1Q 태깅(스위치 간 트렁크 구간에서만 VLAN 태그 부착), 네이티브 VLAN(태그 없이 지나가는 예외 VLAN, 보안상 분리 권장), DTP(desirable=적극 제안·auto=수동 수락·mode trunk=고정) 협상 방식. auto끼리는 트렁크 안 맺어짐, 실무에선 협상(DTP) 꺼두고 고정하는 게 보안상 안전함을 확인 문제로 점검
  - 확인 문제 3개 중 1개(auto-auto 트렁크 안 맺어짐)는 바로 맞혔고, 네이티브 VLAN 태깅 여부와 DTP 보안 방향(꺼두는 게 안전)은 개념 설명 듣고 교정함

**CCNA 덤프 10문제 중 9개 오답(d2-287만 정답), 개념별 정리**
- LACP 모드: active=적극 제안, passive=응답만(d2-366)
- ACL로 모든 인터페이스 관리 접속 차단: 물리 인터페이스가 아니라 VTY 라인에 access-class로 적용해야 함(d2-512)
- NAT 방향: PC 쪽이 inside, 외부가 outside, static NAT는 "실제 주소 → 변환 주소" 순서, 반대쪽에 돌아오는 경로 필요(d2-528)
- Split MAC 구조: 실시간 기능(비콘·ACK)은 AP가, 관리 기능(인증·로밍)은 WLC가 처리(d2-292)
- 방화벽 기능: 다중 컨텍스트 모드 원격 접속 VPN 지원 + URL 기반 필터링(d2-9)
- southbound API: 컨트롤러↔장비(하드웨어) 방향 — 반복 오답(d2-296)
- FHRP 이점: 가상 게이트웨이 통합 + 자동 장애 조치 — 반복 오답(d2-297)
- REST 헤더: Content-Type(보내는 형식) — **어제에 이어 이틀 연속 반복 오답**(d2-285)
- 대규모 VPN: GETVPN·DMVPN — 반복 오답(d2-86)

**복습 퀴즈 5문제 중 2개 정답(Content-Type, PATCH) — 두 개념 모두 드디어 정착된 듯**
- SSID 브로드캐스트는 "체크 해제"가 정답인데 오늘도 "체크해야 해"로 반복 오답
- PortFast 이유를 "사설 IP 주소 쓰는 이유"(더 많은 IP 할당)와 혼동 — 전혀 다른 개념인데 또 섞어서 답함. PortFast는 STP 상태 전환(즉시 forwarding) + TCN 미발생이 정답
- 대규모 VPN 기술(GETVPN/DMVPN)을 몰라서 IPsec으로 답함 — 반복 오답

## 틀린 것
- d2-366, d2-512, d2-528, d2-292, d2-9, d2-296, d2-297, d2-285, d2-86: 위 참고
- 복습: SSID 체크 방향, PortFast 이유(사설 IP와 혼동), GETVPN/DMVPN 3개 오답

## 다시 볼 것
- Content-Type, PATCH는 복습에서 처음으로 맞혀서 정착 후보 — 한 번 더 확인
- PortFast 이유는 세 번째 복습에도 틀리고, 이번엔 아예 다른 개념(사설 IP)과 혼동함 — 설명 방식을 바꿔서 접근 필요
- SSID 브로드캐스트 체크 방향, GETVPN/DMVPN은 계속 추적
