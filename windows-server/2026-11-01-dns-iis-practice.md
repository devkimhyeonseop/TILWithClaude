# 2026-11-01 윈도우 서버 실기 2/3: DNS 영역·레코드, IIS 웹사이트

## 배운 것
- DNS 관리자에서 정방향 영역(`example.com`)을 만들고 A 레코드(`www` → IP)를 추가했다
- 역방향 조회 영역은 네트워크 ID를 **정상 순서의 앞 3자리**(`192.168.10`)로 입력하면 영역 이름이 `10.168.192.in-addr.arpa`로 자동으로 뒤집힌다
- PTR 레코드는 호스트 IP 칸에 **마지막 자리 숫자만** 쓰고, FQDN 줄이 `10.10.168.192.in-addr.arpa`로 나오는지 확인한다
- IIS "웹 사이트 추가": 사이트 이름, 실제 경로, 바인딩(종류·IP·포트·호스트 이름)을 한 창에서 입력한다
- 기본 문서 목록(`Default.htm`, `Default.asp`, `index.htm`, `index.html`)은 서버 설정을 **상속**받는다. 문제의 문서가 이미 있으면 추가하지 않아도 된다
- 포트는 바인딩 편집에서 바꾼다. 기본 웹사이트와 IP·포트가 겹치면 시작이 안 된다

## 틀린 것
- 연습 문제: 역방향 영역과 PTR을 몰랐다 (AAAA로 답함), 웹 문서 폴더 항목을 "기본 문서"로 답함 → **실제(물리적) 경로**
- PTR 레코드를 만들 때 호스트 IP 칸에 전체 IP를 넣어 FQDN이 `192.168.10.10.10.168.192.in-addr.arpa`로 겹쳤다 → 지우고 마지막 숫자 `10`만 넣어 다시 만듦

## 다시 볼 것
- PTR은 끝자리만, FQDN 줄로 반드시 확인
- DNS 도구가 에뮬레이터라서 내 PC에서 `nslookup`으로는 확인되지 않는다 (PC의 DNS 서버는 통신사 서버). 시험에서는 레코드가 만들어졌는지를 본다
